## 优先级评估

| 优先级 | 含义与执行原则 |
| --- | --- |
| P0 | 已证实的安全、数据丢失、未经审批写入或严重核心流程故障；立即停止扩展并修复 |
| P1 | 显著影响核心流程理解/可信度，或补足目标数据库、真实 Agent、交付可靠性的关键证据；近期优先 |
| P2 | 有价值但核心闭环仍可完成的改进或阶段二实验；完成高优先级且证据充分后实施 |
| P3 | 装饰、条件性部署、收益不明或复杂度高的长期项；默认暂缓或限于调研 |

每次较大迭代前及新增重要证据时，审视全部未完成任务（含 deferred）；综合核心流程影响、安全/完整性、真实用户价值、Agent 技术价值、成本/风险/依赖、证据强度和更简单替代方案。按必要性与可实施性排序，不按添加时间，不用虚构评分。低优先级若修复高优先级的前置依赖，说明原因后可先做；环境等待可并行推进独立任务。

成本为单人开发投入估计：S 约半天至 1 天，M 约 1–3 天，L 约 3–7 天，XL 超过 7 天且需先拆分；不含环境等待、素材绘制或未授权模型调用。不是实际耗时、承诺日期或性能数据，实施前复估。
