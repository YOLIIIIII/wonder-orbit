# WonderOrbit 质量评价 v1

版本：`wonderorbit-quality-v1`；案例：`wonderorbit-cases-v1`；来源：2026-11-01 EVAL-001 第一阶段任务书与 AGENT-001 公开质量观察。范围是评价方法与离线设施，没有模型效果提升结论。

## 两种证据

确定性检查只给 passed / failed / not_run / not_rated，不转为质量分数。缺案例结果为 not_run；提供了执行结果但缺输出是 failed；缺审批观察是 not_rated。计数单位是检查项，非模型成功率。语法/版本错误退出 2，已评价且存在确定性失败退出 1，否则退出 0；退出 0 可以仍有未执行和未评分，不能作为完整验收。

人工按每个维度给 0/1/2，并写简短依据；缺观察、未评审或不适用时用 `not_rated` 与原因。未填写评分自动保留 not_rated，绝不填 0。0 是观察到明确问题。没有总分、自动合格线或 LLM Judge；跨版本、证据类型及不同观察层的结果不混算。结构合法不代表质量优秀。

## 确定性检查

| 范围 | 程序判断 | 边界 |
| --- | --- | --- |
| 通用 | 现有 AgentRequest / DraftResult / ProposalResult Schema、结果封装类型、重复/未知案例、版本一致性 | 复用 DTO，不调用模型适配器/图/工具运行时 |
| Collect | 原文与来源逐项相同；固定案例显式未知字段保持 null；明确动机案例保留原文原因；reason 与 missing_fields 一致 | 不是通用语义判定器；其他场景的语义事实需人工判断 |
| Explore | 非空引用属于该案例实际给出的检索 Star 集；时间、预算（含未知成本）、精力与偏好上限；无历史/不支持约束无建议且有问题 | 不访问数据库，只验证公开检索快照。数值满足不证明实际耗时/成本可信 |
| 支持约束 | 复用 SUPPORTED_CONSTRAINTS / TEXT_STEPS；有约束时仅允许既有免费文字模板；未知约束拒绝候选 | 与 ToolRegistry 规则保持一致，后续规则变更需同步复查；不证明自由文本承诺被实现 |
| 审批 | 外部观察的生成前后正式记录计数不增；批准增一、拒绝/未决定不增、重复不再增；批准须声明授权来源 | 仅外部测试观察，不接受模型文本自称批准；缺观察不评分。计数不能证明 API 真正执行，权限/事务仍由既有隔离 API 测试验证 |

输出应是同一观察层：Collect 为 DraftResult，Explore 为 ProposalResult（可记录模型候选或最终候选，但必须通过 workflow_version/备注说明）。检查原始错误候选失败与工作流成功拦截是两个事实，不能互相覆盖。此工具不转换私有 Live runner 历史报告。

## Collect 人工维度

| 字段 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| topic | 主题错误或遗漏核心兴趣 | 大致正确但遗漏次主题或范围失真 | 准确保留核心与次主题；单草稿限制表达合理 |
| title | 误导、空泛或偏离兴趣 | 可识别但范围/重点不清 | 简洁且准确，帮助再次找到兴趣 |
| category | 明显误分类 | 未分类或过宽，查找帮助有限 | 与内容相符且对归档有帮助 |
| tags | 错误/编造标签 | 仅部分有用或缺失 | 有依据、具体、不重复的主题标签 |
| description | 编造或不能表达兴趣 | 基本复述但信息组织有限 | 忠实、清楚地组织兴趣及问题 |
| motivation | 把主题/科学因果/心理猜测当动机 | 未编造但遗漏已明确动机或表达不清 | 准确保留明确动机；未给出则明确未知 |
| clarification | 误导或重复无关追问 | 有用但遗漏重点/内部字段名难懂 | missing_fields 与实际缺口相符，问题少而具体，可帮助补全且不阻断留存 |

原文/来源保真是确定性项；人工同时留意描述是否悄悄改变语义。未知资源的空值与人工 motivation 分开评价。已知明确动机案例复用旧对照，不要求标题/标签/问题采用固定措辞。

## Explore 人工维度

| 字段 | 0 | 1 | 2 |
| --- | --- | --- | --- |
| relevance | 与兴趣无关或理由编造 | 有主题联系但依据弱 | 内容及理由直接对应检索 Star 的真实兴趣 |
| feasibility | 依赖未提供资源或明显不可行 | 数值满足但耗时/预算/精力估计依据薄弱 | 当前资源内可做，估计与步骤相符，边界清楚 |
| steps | “想想/试试”等无法开始 | 能开始但关键步骤含糊 | 有具体动作、对象及可辨认的结束结果 |
| uncertainty | 无依据保证价格/知识/体验效果 | 有笼统提示但未指出关键未知 | 指出本次相关未知、限制与需要确认的前提 |
| exploration_value | 无具体收获或只换词套模板 | 有小收获但兴趣适配弱 | 对该兴趣提供值得尝试的新问题/观察/行动 |

固定文字模板可以安全，也可能质量低；安全约束要求模板时不因“重复模板”自动给 0，而看是否仍有具体探索收获。无建议的澄清案例，不能观察的步骤/价值等标记 not_rated，不因安全拒绝自动给满分。用户真实执行效果本阶段不可观察；不以模型声称“有趣”代替效果证据。

## 使用与比较

格式和命令见 [README](README.md#offline-quality-v1)。本轮未优化 Prompt/切换模型；没有新的真实质量基线。未来获得独立调用授权后，在同一案例版本上保存公开输入/输出与真实版本，再人工评分；先比较逐项失败和人工备注，样本少时不推断总体准确率。无法得知的版本用 unknown/not_recorded，不能用评测器版本替代实际生成版本。
